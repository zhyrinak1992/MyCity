# My City Unity v1.6.17 — финансовая сверка розничных поставок

## Что изменено
- Исправлена проверка состояния акта: API фиксации фактического и повреждённого количества теперь принимает данные только в реальном состоянии «Ожидает приёмки» (до этого проверка ожидала «В пути в магазин», хотя логистика меняет статус на «Ожидает приёмки» при прибытии).
- В `StoreDeliveryRecord` добавлены сохраняемые поля сверки: первоначальная стоимость закупки, возврат за недостачу, чистая стоимость партии, стоимость товара в принятом запасе, стоимость повреждённого товара, фактический фрахт и распределение фрахта.
- Приёмка рассчитывает точное распределение оплаченной стоимости товара между пригодным запасом и повреждёнными единицами. Остаток округления назначается детерминированно, поэтому сумма частей равна чистой стоимости партии.
- Фактический фрахт рейса списывается с баланса магазина один раз при приёмке. Если баланс недостаточен, отрицательный остаток представляет обязательство магазина, а расход не теряется.
- Фрахт распределяется между пригодным запасом и повреждёнными единицами; если физически не прибыло ни одной единицы, он отражается как отдельный некапитализируемый логистический расход.
- В `WorkplaceRecord` добавлены дневной и накопительный показатели транспортных расходов.
- В `CityEconomySystem` добавлена защита от повторного проведения транспортного расхода в накопительном финансовом журнале.
- Приёмка выставляет `IsFinanciallyReconciled` только если сходятся все контрольные равенства и подтверждены обязательные операции возврата/списания/проведения фрахта.
- Новые поля добавлены к существующим сериализуемым записям; отдельная миграция схемы не требуется, старые сохранения получают нулевые значения новых полей.

## Контрольные равенства
1. `GrossPurchaseValue = ShortageRefundValue + NetPurchaseValue`.
2. `NetPurchaseValue = GoodsCostAllocatedToInventory + GoodsCostWrittenOff`.
3. `FreightCostCharged = FreightAllocatedToInventory + FreightAllocatedToDamage + FreightUnallocatedExpense`.
4. Товарный остаток увеличивается только на `AcceptedUnits` (получено минус повреждено).

## Важные правила
- Возврат за недостачу возвращает только стоимость отсутствующего товара; транспортный рейс уже состоялся, поэтому фрахт не возвращается автоматически.
- Повреждённый товар не попадает в продаваемый запас. Его стоимость классифицируется как ущерб, но не списывается с денежного баланса второй раз: закупка уже была оплачена.
- Фрахт списывается с баланса отдельно от закупочной стоимости и не дублируется при повторной обработке акта.
- Отчётные значения являются управленческим игровым учётом прототипа, а не полноценной бухгалтерской/налоговой системой.

## Статические проверки
- Проверены целостность ZIP, наличие новых полей и вызовов, баланс фигурных скобок в изменённых C# файлах.
- Расчётные сценарии проверены скриптом на целочисленных суммах и остатках округления.
- Unity Editor, компилятор C# и Play Mode в среде подготовки недоступны; компиляция, сохранение/загрузка и игровой прогон не подтверждены.
