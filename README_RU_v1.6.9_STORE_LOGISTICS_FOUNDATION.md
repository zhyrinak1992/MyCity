# My City v1.6.9 — основа резервирования магазинной логистики

Основа следующего этапа физической доставки товаров в магазины.

## Что изменено
- В складской остаток добавлено поле `ReservedUnits`.
- В `WarehouseRecord` добавлен сохраняемый журнал `StockReservations` с ID заказа, товаром, количеством и днём создания.
- `GetAvailableStock` отделяет физический остаток от свободного для новых заказов.
- `TryReserveStock` резервирует товар атомарно по стабильному ID; повторный запрос с тем же ID идемпотентен.
- `ReleaseReservedStock` снимает резерв по ID заказа.
- `TryConsumeReservedStock` списывает именно зарезервированную партию по ID, возвращая среднюю себестоимость.
- Обычный `TryWithdraw` больше не может забрать товар, уже зарезервированный под другой заказ.
- При загрузке старых/новых сохранений резервные количества пересчитываются из журнала; старые сохранения без журнала остаются совместимыми.

## Важно: статус реализации
Это **фундаментальный подэтап**, а не законченная доставка магазинам. На следующем этапе необходимо связать магазинный `StoreDeliveryRecord` с ID резерва, физическим рейсом, очередью дока/погрузки, дорожным маршрутом, приёмкой и фрахтом. Пока существующая автоматическая поставка по календарной дате не заменена полностью.

## Проверки
Выполнены статические проверки исходников и структуры изменений. Unity Editor в среде подготовки отсутствует; компиляция и Play Mode не подтверждены.
